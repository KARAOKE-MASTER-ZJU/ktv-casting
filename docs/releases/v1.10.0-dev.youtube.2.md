# v1.10.0-dev.youtube.2

修复 YouTube 投屏准备阶段后续 Range 返回 403，导致 `upstream did not return the exact requested range`。

- 显式使用已有 innertube-rs 的 VISIONOS player 接口，避免高层 API 静默回退到需要额外认证的 IOS 媒体地址。
- DASH 索引和媒体缓存请求统一使用对应客户端的 User-Agent；Bilibili 请求保持原样。
- 上游 HTTP 错误显示真实状态码和请求范围，不打印包含签名的 URL。
- 无新增依赖，不依赖 yt-dlp、Python、V8/Deno、外部 token 服务或外部进程。仅参考 yt-dlp 当前客户端选择策略，复用项目已有的纯 Rust DASH 混流和本地代理。

本机对故障视频 `_1gTMhvRtB8` 验证 720p 和 1080p，均生成 H.264 + AAC、241.301 秒的 MP4，HEAD 及首/中/尾三个 64 KiB Range 全部通过。默认库测试通过；网络测试需显式运行：

```sh
cargo test --locked --lib
cargo test --locked --lib youtube_parser::tests::public_video -- --ignored --nocapture --test-threads=1
```

依然只支持公开、可访问且提供带索引 H.264/AAC MP4 轨道的视频；部分儿童内容或受限视频可能被该客户端拒绝。网络代理验证不代替 Android 真机与电视解码验证，本版保持预发布。

App 对应版本：`v1.9.0+dev.youtube-recast.2`，Rust 依赖：`v1.10.0-dev.youtube.2`。
