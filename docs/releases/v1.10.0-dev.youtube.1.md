## 整合调整

- 重新投屏总超时从 30 秒增至 120 秒，覆盖 YouTube 解析（30 秒）和 DASH 索引准备（60 秒），继续保留重复操作拦截和旧进度隔离。
- Android 初始化同时配置会话和曲目缓存目录。JNI 保留最新 KARAOKE App 所需全部接口。
- PR 验证四个 Android ABI 和三个桌面 CLI；只有全部构建成功才发布 Release，并附 `SHA256SUMS`。
- 默认库测试不访问外部房间、不操作真实电视；网络及设备测试需显式指定 `--ignored`。

## 验证命令与限制

```sh
cargo test --locked --lib
cargo test --locked --lib youtube_parser::tests::public_video_1080p_can_prepare_for_dlna -- --ignored --nocapture
```

YouTube 只支持公开且能解析出带索引的 H.264/AAC MP4 双轨的视频；不依赖 yt-dlp、Python 或外部进程。电视只获取本地代理的 MP4 URL。直播、受限视频、登录验证和完整 YouTube 播放列表不在本次支持范围。

网络代理测试验证 MP4 轨道、尺寸、HEAD 和首/中/尾 Range 响应，不等于 Android 真机或电视解码回归，因此本版保持预发布。

## App 联动

App PR 必须从 `KARAOKE-MASTER-ZJU/ktv-casting-android-app` 最新 master 创建，保留新版切歌流程、重新投屏按钮及现有 720P/1080P 控件，仅将 `gradle.properties` 的 `rust_libs_version` 更新为本 tag。Rust PR 与 App PR 在 GitHub 上互相引用；本次不发布 App tag。
